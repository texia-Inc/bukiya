# 武器屋放置ゲーム 総合設計書 v2.0

## 1. ゲーム概要

### 基本コンセプト
**テーマ**: 武器屋経営放置ゲーム  
**プラットフォーム**: Flutter (iOS/Android対応)  
**技術スタック**: Flutter + Python FastAPI + PostgreSQL  
**UI方針**: テキストメイン、AI生成武器画像活用

### 核心的ゲームループ
```
冒険者来訪 → 武器販売 → 冒険派遣 → 素材・武器獲得 → 
錬成・エンチャント → より強い武器作成 → 高難度モンスター挑戦
```

### ユニークな特徴
- **時間制限付き買取システム**: 冒険者が持参する素材・武器の買取期限
- **エンチャントエフェクト**: +5以上で視覚エフェクト、+20以上で特別演出
- **関係性重視**: 冒険者との信頼関係がゲーム進行に影響
- **無限拡張**: 新モンスター追加による継続的なコンテンツ拡張

## 4. システム設計詳細

### 冒険者システム
#### 基本フロー
```
1. 冒険者来訪（要求武器を提示）
2. プレイヤーが武器選択・価格交渉
3. 冒険者が武器を持って派遣
4. 一定時間後に帰還（素材・武器持参）
5. 時間制限内での買取判断
6. 信頼関係の変動
```

#### 冒険者パラメータ
- **基本情報**: 名前、職業、レベル、性格
- **特性**: 好む武器種、予算範囲、交渉スキル
- **関係性**: 信頼度、取引履歴、特別な関係

### 武器生成システム
#### 段階的複雑化
```
Phase 1 (初期): 基本武器種×レア度の組み合わせ
Phase 2 (1ヶ月): 属性システム導入
Phase 3 (3ヶ月): 武器カスタマイズ・分解システム
Phase 4 (6ヶ月+): プレイヤー命名権・創造システム
```

#### 武器構成要素
- **ベース**: 武器種（剣、弓、杖、斧、槍）
- **レア度**: 5段階（Common〜Mythic）
- **属性**: 5大属性（火、氷、雷、土、風）
- **アビリティ**: 特殊効果（レア度に応じて1-3個）
- **エンチャント**: +0〜+30の強化レベル

### モンスター・エリアシステム
#### エリア階層
```
森林（初級）: 基本モンスター、店舗Lv1で解放
洞窟（中級）: 中級モンスター、店舗Lv5で解放
山岳（上級）: 上級モンスター、店舗Lv10で解放
遺跡（特級）: レジェンダリー、特別条件で解放
異界（神話級）: ミシック級、エンドコンテンツ
```

#### モンスター特性
- **基本ステータス**: HP、攻撃力、防御力、属性
- **特殊要求**: 特効武器、最低エンチャントレベル
- **ドロップテーブル**: 確率的な素材・武器獲得

## 5. 画面設計・UX

### 画面構成
1. **ホーム画面**: 現状確認・クイックアクション
2. **冒険者画面**: 取引・派遣管理・帰還対応
3. **工房画面**: 錬成・エンチャント
4. **倉庫画面**: 武器・素材管理
5. **ランキング画面**: SNS・競争要素

### 情報アーキテクチャ
#### 緊急度による表示優先度
```
🔴 緊急: 買取期限5分以下、システム重要通知
🟡 注意: 買取期限30分以下、冒険者滞在終了間近
🟢 通常: 日常的な冒険者取引、錬成状況
⚪ 情報: 統計、ランキング、お知らせ
```

### プレイヤー体験フロー
#### 日常的な操作パターン
```
1. アプリ起動→ホーム画面で状況確認
2. 完了した活動（派遣・錬成）を回収
3. 新しい冒険者との取引
4. 帰還した冒険者からの買取判断
5. 新しい錬成・派遣を開始
6. アプリを閉じて放置
```

## 6. 技術設計

### システム構成
```
フロントエンド: Flutter (Riverpod状態管理)
バックエンド: Python FastAPI
データベース: PostgreSQL 15+
キャッシュ: Redis
インフラ: VPS (Docker構成)
```

### データベース主要テーブル
```sql
-- プレイヤー関連
players, player_statistics, player_weapons, player_materials

-- マスタデータ
weapon_masters, material_masters, monster_masters
weapon_types, rarity_levels, attributes, abilities

-- ゲームシステム
crafting_recipes, monster_drop_tables, active_processes
adventurer_visits, trade_logs

-- 管理・運営
admin_logs, player_adventurer_relationships
```

### API設計方針
```
ゲームAPI: /api/v1/* (プレイヤー向け)
管理API: /admin/v1/* (運営向け)
認証: JWT Bearer Token
レスポンス: 統一JSON形式
エラー: 体系化されたエラーコード
```

## 結論

この設計書により、技術的に実現可能で商業的に成功の見込みがある武器屋放置ゲームの全体像が完成しました。

**主要な成功要因:**
1. **差別化された体験**: 時間制限取引と関係性重視のユニークなゲームプレイ
2. **技術的優位性**: 管理画面ファースト開発による効率性と拡張性
3. **持続可能な運営**: 新モンスター追加による無限コンテンツ拡張
4. **バランスの取れた収益化**: 強制感のない自然な課金誘導

この設計に基づき、高品質なMVPを3-4ヶ月で開発し、継続的な成長を実現できる基盤が整いました。
